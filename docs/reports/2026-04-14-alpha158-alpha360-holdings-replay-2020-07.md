## 4. 为什么这个局部优势没有转成 formal-task 的最终净值胜出？

### 4.1 不是这 3 天的即时交易成本导致的

三天窗口累计成本（commission + slippage）：
- alpha158:
  - `2020-07-01 = 483.593024`
  - `2020-07-02 = 491.150070`
  - `2020-07-03 = 501.503242`
  - 合计 `1476.246336`
- alpha360:
  - `2020-07-01 = 481.449451`
  - `2020-07-02 = 484.495166`
  - `2020-07-03 = 500.719240`
  - 合计 `1466.663857`

结论：
- 这 3 天两边即时成本几乎一样，alpha360 甚至还略低一点。
- 所以“为什么 7/1~7/3 没直接把 alpha158 打过去”，答案不是这 3 天的成本摩擦。

### 4.2 真正的原因是：alpha360 只是追回了前面已经形成的 deficit，而且全窗累计成本更高

到月末 `2020-07-31`：
- net final value
  - alpha158: `976606.992`
  - alpha360: `973679.386`
  - alpha158 仍领先 `2927.606`
- gross final value (`portfolio_value_without_cost`)
  - alpha158: `1029312.991`
  - alpha360: `1029756.964`
  - alpha360 略领先 `443.974`
- full-window cumulative total_cost
  - alpha158: `52705.999`
  - alpha360: `56077.578`
  - alpha360 多花 `3371.580`

所以最准确的说法是：
1. alpha360 的 `2020-07-01~2020-07-03` 分歧选择，确实带来了 realized 改善。
2. 但这更像“追回前面损失 + 在 gross 口径上略占优”，而不是足以改写全窗正式任务结果的决定性反转。
3. 真正把 gross 微弱优势翻成 net 落后的，是全窗更高的累计成本；而不是这 3 天局部执行本身出了问题。

## 5. 一句话结论

如果只盯 `2020-07-01~2020-07-03`：
- alpha360 确实更好，真实持仓也验证了它更早把 `600036.SH` / `000001.SZ` 这类强弹性票装进了组合路径。

但如果问“为什么这没有转成 formal-task 最终胜出”：
- 因为它在进入这段窗口前已经落后较多，三天只是追回不是反超；
- 到 7 月末 gross 已经几乎打平甚至略赢，但 full-window 累计成本比 alpha158 多 `3371.580`，最终把这个局部优势吃回去了。
