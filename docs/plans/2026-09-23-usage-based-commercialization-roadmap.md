# 按使用量商业化改造路线图

> **目标**：把股票预测平台从订阅制 SaaS 转型为按使用量计费模式，实现真正的"赚用户点击使用量"。

## 🎯 核心目标

把平台变成用户**点一次就赚一分钱**的模式：
- 每次回测 → 收费
- 每次API调用 → 收费  
- 每次数据查询 → 收费
- 超出后继续收费（不是砍功能）

## 📊 当前 vs 目标

| 项目 | 当前状态 | 目标 | 差距 |
|-----|---------|------|------|
| 计费模型 | 订阅制（固定月费） | 按量付费（每次消耗即付） | 需新增计费事件模型 |
| 超额处理 | 限制次数，超出不可用 | 超额继续收费，提示续费 | 需超额计费逻辑 |
| 收入模式 | 月/年订阅 | 单次/按量 | 需变更计费逻辑 |
| 用量展示 | 剩余次数 | 已消耗 + 剩余 + 应付款项 | 需前端/后端联调 |

## 🏗️ 实施阶段

### 阶段 1：计费事件模型（1-2周）

**目标**：定义每次操作的"钱数"

```
backend/app/models/commerce_models.py
├── UsageEvent (用量事件表)
│   ├── event_type: 回测/策略/API/数据
│   ├── unit_cost: 单位费用（分）
│   ├── quantity: 消耗次数
│   └── total_cost: 总费用
├── UserBalance (用户余额)
│   ├── balance_cents: 当前余额（分）
│   └── credited_cents: 赠送额度
└── BillingRecord (账单记录)
    ├── usage_event_id
    ├── charge_status: 待扣/已扣/失败
    └── charge_amount: 实际扣费
```

**计费规则（示例）**：
| 事件类型 | 单价 | 业务逻辑 |
|---------|------|---------|
| 基础回测 | ¥0.5/次 | 数据库已导入的历史数据 |
| 实时回测 | ¥2/次 | 需要实时行情 |
| 高级策略 | ¥1/次 | 多因子/深度学习 |
| API调用 | ¥0.01/次 | 公共API |
| 数据下载 | ¥0.05/次 | 现场文件CSV |
| 实时行情 | ¥0.05/次 | WebSocket推送 |

### 阶段 2：用户钱包/充值系统（1周）

**后端 API**：
- `POST /commerce/wallet/deposit` - 充值
- `POST /commerce/wallet/record` - 扣减
- `GET /commerce/wallet/balance` - 查余额
- `GET /commerce/billing/history` - 查账单

**前端页面**：
- `/wallet` - 钱包页面
- `/billing/history` - 账单历史
- 充值弹窗（支付宝/微信/信用卡）

### 阶段 3：用量自动扣费（1周）

**逻辑**：
1. 每次触发计费事件 → 查用户余额
2. 余额足够 → 直接扣，生成账单
3. 余额不足 → 标记"待缴"，允许继续使用（信用）
4. 周期结束 → 强制续费

**Stripe 改造**：
- 从订阅制 → 一次性收款 + 按量计费
- 或保留订阅 + 超额分单

### 阶段 4：前后端联调（1周）

**前端用量页**：
```
用量概览
├── 回测：12/50 次（¥6/¥25 已花/总额度）
├── API调用：841/1000 次（¥8.41/¥10 已花/总额度）
├── 数据查询：12/100 次
└── 账户余额：¥15.23
```

**提醒**：
- 用量 80% → 弹窗提醒
- 余额不足 → 限制+充值入口
- 账单生成 → 发送邮件

## 💰 费用结构设计

### 免费版（Free）
- 赠送 ¥10 初始额度
- 50 次回测 + 1000 API 调用
- 超额 ¥0.5/次（回测）、¥0.01/次（API）

### 专业版（Pro）
- 月费 ¥99 = 赠送 ¥200 额度
- 1000 次回测 + 20000 API 调用
- 超额 ¥0.3/次（回测），¥0.005/次（API）

### 企业版（Enterprise）
- 团队套餐 + 自定义计费
- 按使用明细结算

## 🚀 MVP（最小可行产品）

**最小实现**：
1. 定义3种核心计费事件：回测、API调用、数据查询
2. 每种事件固定价：回测¥1、API¥0.01、数据¥0.05
3. 用户可以查看用量+余额
4. 用量耗尽后停止（不强制扣费，等充值）

**MVP 价值**：
- 证明"按量计费"有商业价值
- 用户会看到"这次操作花了我 ¥1"
- 收入比订阅更可预见
