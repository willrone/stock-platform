# 股票平台质量提升计划

## 目标：8 维度 → 90 分

## 现状评估（来自架构审查 + 代码检查）

| 维度         | 现状分 | 目标分 | 缺口                                                  | 优先级 |
| ------------ | ------ | ------ | ----------------------------------------------------- | ------ |
| 功能可用性   | 65     | 90     | 缺少用户引导、任务模板、数据流可视化                  | P0     |
| 易用性       | 45     | 90     | 无 proper landing page、新手引导、操作反馈            | P0     |
| 代码质量     | 65     | 90     | dependencies.py 大文件、双错误体系、TS 类型修复       | P0     |
| 框架质量     | 70     | 90     | Flask→FastAPI 迁移半成品、数据库升级、monitoring 完善 | P1     |
| 前端质量     | 55     | 90     | 组件粒度不够、loading/error 态不统一、主题系统薄弱    | P1     |
| 前端可维护性 | 60     | 90     | 大页面拆分、组件按功能组织、加 Storybook、目录规范    | P1     |
| 前端排版     | 50     | 90     | 响应式修复、间距一致化、布局系统化                    | P2     |
| 前端美观     | 45     | 90     | 品牌色系统、动效、图标规范、暗色模式                  | P2     |

## 行动方案

### P0：功能可用性 + 易用性 + 代码质量

**P0-1：用户首次体验流**

1. Landing page（Hero + 特性 + CTA）
2. 注册后引导（3 步：创建策略 → 运行回测 → 看结果）
3. 预设策略模板（3 个开箱即用的策略）
4. 操作反馈（Toast、进度条、空态展示）

**P0-2：代码紧急修复**

1. `dependencies.py` 拆解（移走 task executors）
2. `error_handler.py` 与 `errors.py` 合并收尾
3. 修复所有 TS 构建错误（`tasks/tuning/page.tsx` 的 `apiRequest` 调用）
4. `pyproject.toml` 版本对齐

### P1：前端质量 + 可维护性 + 框架质量

**P1-1：前端组件体系**

1. 统一 `@/components/ui/` 基础组件（Button、Card、Input 等包装）
2. 拆分超大页面（`models.py` → `models/training.tsx` + `models/list.tsx`）
3. 所有 API 调用加 loading/error 态
4. 前端目录规范和 index 导出

**P1-2：框架补齐**

1. 后端 route 统一认证（已完成）
2. 数据服务 Flask→FastAPI 迁移（评估）
3. 监控面板（请求量、错误率、响应时间）

### P2：前端排版 + 美观

**P2-1：设计系统**

1. MUI theme 完善（品牌色、间距、圆角、阴影）
2. 暗色/亮色模式切换
3. 图标规范（HeroIcons + MUI Icons 统一）
4. 排版系统（字体层级、间距系统）

**P2-2：页面美化**

1. Dashboard 重设计（KPI 卡片、图表、网格系统）
2. 登录/注册页打磨（背景、动效）
3. 全局 Navigation 美化
4. 响应式断点补齐
